# Changelog

All notable changes. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- 2026-07-29 (ADR-044): **push carries only card types that can change the next action.** New `push_types` config, default `gotcha`/`error_fix`/`preference`. Across 197 real inject servings, 73% of the budget had gone to `decision`, `fact` and `doc_ref` — reference material that is worth looking up and worthless as an interruption. Those types stay fully reachable by asking (`recall`/`why`/`for_file`/`lookup_error`); only the unasked-for surface narrows. Push now stays silent more often, which is Manifesto P3 rather than a regression.

### Added
- 2026-07-29 (ADR-046): **the nightly run's time is now a setting.** New `run_time` in config.toml and a native time picker in the Settings tab (default 02:30). One validated value threads into whichever scheduler this machine uses — systemd timer, launchd agent, Windows Task Scheduler, or crontab. Saving a new time reapplies an already-installed scheduler immediately; if the nightly was never scheduled, the save says so instead of installing one behind your back. Also fixes schtasks idempotence, which compared the command only and reported a pure time change as "unchanged".

- 2026-07-29 (ADR-045): **curated card links: kNN proposes, an LLM judges, and only judged links exist.** 89% of active cards had no edge at all — file coupling is capped at 23% by construction and the distiller cannot emit wikilinks (it sees one session, never the corpus). New `afterwit relink`: top-8 cosine neighbours from the stored vectors are offered to a judge that keeps at most 3; kNN output itself is never surfaced. Kept ids land in a machine-owned `related:` frontmatter key (rebuild-lossless), mirror to `links(kind='related')`, and show up in the graph page and the `related` MCP tool. The links land without per-link review — the judge selects from a closed set so it cannot fabricate a target, links never touch ranking or injection, and `afterwit relink --strip` erases the whole class in one command. Off by default (`relink_budget = 0`) until a hand-judged precision sweep over `relink --dry-run` output passes.

- 2026-07-27 (ADR-040): **`afterwit doctor` checks the Codex hooks, and asks Codex whether they will actually run.** Registered is not running: an untrusted hook is skipped with no warning at all, and any edit to a hook re-breaks its trust. Doctor now reports both hooks' presence and their live `trustStatus` from `hooks/list`, naming the offending event when one is `untrusted`/`modified`.

- 2026-07-27 (ADR-040): **Codex gets the same push surfaces as Claude Code.** `afterwit install codex` now registers `SessionStart` and `UserPromptSubmit` hooks in `~/.codex/config.toml` alongside the MCP server, under the same Manifesto P3 caps (≤3 cards, ≤600 tokens, threshold-gated). This supersedes ADR-003's "Codex = session-start doc + MCP-pull", which held only while Codex had no hook system: codex-cli 0.145.0 ships `hooks` as a stable, on-by-default feature whose payload keys are byte-identical to Claude Code's, verified end-to-end against a real `codex exec` run. Codex gates hooks behind a persisted trust hash and skips untrusted ones **silently**, so install also reads `codex app-server` `hooks/list` and writes the matching `[hooks.state.…]` entries — for its own hooks in its own file only, never a hook it did not write. The error hook is deliberately *not* ported: Codex has no `PostToolUseFailure`, and its `PostToolUse` fires on success and failure with identical payloads (Gotchas #69, #70).

- 2026-07-27 (ADR-039): **a project's slug no longer has to match its folder name.** New `[project_aliases]` table in `config.toml` maps folder → slug. Until now `project_from_cwd` returned the directory name verbatim, so a project could not be renamed without moving it: the session line is a hard project filter and went 112 cards → 0, ranking lost its +0.15 same-project boost (enough to drop a card below the floor), and the adapters re-stamped the old slug on every new card so the rename undid itself on the next nightly. This repo is now `afterwit` while its directory stays `harness_helper` — 121 cards, the wiki directory, the `projects` row and 11 review-queue entries migrated, verified against a baseline taken first.

- 2026-07-23 (ADR-034): **a Settings surface in `afterwit ui`** (tab 5). Driver, model, reasoning effort, auto-review, injection caps and paths are all editable from the browser and written back to `~/.afterwit/config.toml` — comments, ordering and `[[databases]]` tables preserved, a timestamped backup taken first, and any write that cannot be read back refused. Saving reloads the running server's config, so the change applies without restarting `afterwit ui`. Injection caps are bounded in the schema (≤3 cards / ≤600 tokens) so the page cannot be used to break Manifesto P3.
- 2026-07-23 (ADR-034): **model and effort choices come from each harness's own config.** The model box offers what Claude Code and Codex actually have on this machine — Claude Code's configured `model` plus its `additionalModelOptionsCache`, Codex's `model`, `profiles.*.model`, `tui.model_availability_nux` and `notice.model_migrations` — instead of a list baked into afterwit that is wrong the day a model ships. It is a dropdown with an "Other…" escape hatch for an id that shipped today (and a model already in your config that no harness lists is kept and marked "current"), so an unknown id is never rejected. The page also shows each detected harness: config file, its own model/effort, transcript folder, and whether afterwit's MCP server is registered there.

- 2026-07-23 (ADR-035): **cards now record who made them.** New `distilled_by` frontmatter field carries `driver:model:effort` for the model that extracted the card (`agent` for `save_insight`/`afterwit queue` proposals, `deterministic-import` for parsed docs), and `reviewed_by` now carries the same resolved shape instead of a bare driver name. The review UI shows the distiller as a chip and `harness · model · effort` on every source line.

### Fixed
- 2026-07-29 (ADR-043, Gotcha #81): **usage mining measures what a card added, not whether its title echoes.** The old rule scored a served card `used` when 60% of its title tokens showed up later — and said the same for 95.7% of real card-servings against 54.0% of *unrelated* sessions, a lift of 1.8x. It fed the `usefulness` rank term, the decay, and the kill switch, so the gate that exists to disable injection when it stops earning its slot could never fire, and every hit rate derived from it was noise. The rule now scores the card's body tokens less its title, less the query, less what the session had already said **before** the card arrived: 43.9% own against 5.9% held-out, 7.5x. Corpus-rarity weighting was measured and rejected (98% of titles already carry a corpus-rare token — rarity is not the axis), as was requiring the *title* tokens to be novel (0.5% recall: an error_fix card shares its title with the stack trace that matched it, by construction).
- 2026-07-29 (ADR-043): **explicit `feedback` now overrides the mined guess** on the serving it rates, instead of being invisible to the kill switch. Substituted, never added — those rows are positive-only in practice, and adding them would bias a safety gate toward staying on.
- 2026-07-29 (ADR-043): **`afterwit run --remine`** discards mined verdicts and re-judges every past serving. `usefulness` accumulates, so without it a corrected miner stacks on top of the broken one's numbers forever. Explicit feedback survives the reset and replays.
- 2026-07-29 (Gotcha #82): **`writes.` was a token that could never match.** `_WORD` admits `.` because `127.0.0.1` and `pdf.ts` are worth matching on — which also attached a period to every sentence-final word in every card body, silently killing part of each card's evidence. Interior dots survive, edge dots no longer do. Retuning after the fix moved the chosen rule's lift from 12.6x to 7.5x: the bug had been flattering the measurement.
- 2026-07-29 (Gotcha #83): **one unknown record type no longer emits 585 KB of warnings.** `claude_jsonl` warned per *occurrence*; a single transcript carrying `file-history-delta` on thousands of lines buried the output of the command that triggered it. The type itself is the CLI's per-edit undo journal — the sibling of the already-dropped `file-history-snapshot` — and is now dropped; `warn_once` keys on `(file, type)` so the next unannounced type is bounded too, and still loud once.
- 2026-07-28 (ADR-042): **a card from another project is now demoted, and an error lookup is exempt.** `index_db.search()` took a `project` argument and never filtered on it — it only widened the candidate limit — so the only project signal was ranking's `+0.15` same-project boost, which cannot push a foreign card below an absolute floor. Foreign cards are now multiplied by 0.75 (`global` exempt). Measured, not guessed: in this user's mined servings foreign cards were used 3/7 = 43% against same-project 32/43 = 74%, so they are demoted rather than filtered. Error lookups pass 1.0, because replaying every scored serving showed the penalty killing a card that had been mined as *used* — an ESM-loader `ERR_MODULE_NOT_FOUND` fix matched from a different project. A stack trace is a property of the runtime, not of the repo it fired in. Eval re-run: recall@3 100%, MRR 1.000, trap precision 100%.
- 2026-07-28 (ADR-042): **injected cards now carry their id**, so `feedback(card_id, …)` can name one. Push is where most exposures happen, and until now only cards pulled through `recall`/`why` could be rated at all.
- 2026-07-28 (ADR-042): **the error hook matches on the failing command, not only its output.** A `| tail -3` or a summarising test runner drops the signature and the hook went quiet on failures it held a card for; one real serving matched on nothing but `Command timed out after 2m 0s` and returned an unrelated card. The command is prepended, so it lands inside the 12-token window `rank._coverage` scores.
- 2026-07-28 (Gotchas #77, #78): **cards now record the model that actually ran, and how much of the session it read.** `distilled_by` stamped the *configured* name, so a machine with `model = "opus"` wrote `claude-p:opus` — an alias that means one thing today and another after the next release, in the field that exists to say which model wrote a card. Both drivers now resolve it per call: Claude from `--output-format json` (`modelUsage`), Codex — whose event stream carries usage but no model — from `turn_context` in the rollout its own run wrote. Same cards now read `claude-p:claude-opus-5:high` and `codex:gpt-5.6-sol:high`, both verified live. Separately, a session truncated to fit the prompt cap left exactly the trace of a complete one, so a card could rest on half the evidence with nothing recording it: coverage is measured and reported in the run summary, the synced device log (`distill-partial … read 53% (middle elided, 15/1008 turns clipped) of 438,522 chars`) and a new ledger column. Also fixed: the ledger counted only cards that landed active, so a session that proposed 10 cards for review recorded `cards: 0` and `stats` called it a zero-card session.
- 2026-07-27 (Gotcha #75): **afterwit had never distilled a single session on Windows.** Both drivers piped the prompt with `subprocess.run(..., text=True)` and no `encoding=`, which is cp1252 there, and `prompts/distill.md` carries `≤` at position 90 — so every session failed with `'charmap' codec can't encode character '≤'` and each nightly ended `distillation attempted but every session failed (30 skipped)`. The only trace was `Last Result: 1` in Task Scheduler; `doctor` reported all good throughout, because reachability was never the thing that was broken. Fixed at the three boundaries that carry non-ASCII — both distill drivers, doctor's hook spawn (whose stdout is card text) and the Codex `app-server` reader — with `encoding="utf-8", errors="replace"`. Verified on the machine that found it: `distilled 1 sessions (0 skipped) … 10 queued`, against 30/30 skipped the night before.
- 2026-07-27 (Gotcha #76): **doctor spawned a Codex hook string that was not the one on disk.** The check exists to run exactly what is registered, but read the TOML value with `.strip('"')`, leaving a Windows path's backslashes doubled. It passed regardless — Windows collapses duplicate separators — so it was wrong and green at once, in the one check written to catch precisely that. Values install wrote with `json.dumps` are now read back with `json.loads`.
- 2026-07-27 (Gotcha #74): **the Codex install tests were passing by accident.** `_codex_hooks_list` probed `shutil.which("codex")` before consulting its injected transport, so on any machine without codex installed the tests bypassed the function entirely — green locally, two failures and three vacuous passes across all six CI jobs. The injected transport now wins over the environment probe, and a regression test asserts the stub is reached with `which` returning None. A second, Windows-only failure in the same test was a raw-path string match against a key that `json.dumps` had escaped; trust entries are now asserted by parsing the TOML, with a `PureWindowsPath` round-trip test that runs everywhere.

- 2026-07-27 (ADR-041, Gotcha #73): **`save_insight` no longer loses the insight when it cannot stamp provenance.** A long-running MCP server keeps the modules it imported at startup, so one started before `project_dir_name` existed failed every `save_insight` with `ImportError: cannot import name 'project_dir_name' from 'afterwit.config'` — naming a file that defines it — while `recall` kept working. The card is now queued unanchored and the reply says what actually happened (restart the harness). A genuine anchoring bug still raises.

- 2026-07-27 (Gotcha #68): **Codex's documented CLI fallback was a bash syntax error** whenever the checkout path contained a space or parenthesis — `.../OneDrive - Org (Head Office)/...` produced `syntax error near unexpected token ('`, so the one path an agent takes when MCP is unavailable was dead exactly where it was needed. Shell-quoting the value cannot fix this: bash word-splits an expanded `$AW` but does not re-parse quotes, so the quote marks would be looked up as part of the filename. Install now binds a shell function (`aw() { ... "$@"; }; AW=aw`), which leaves every `$AW ...` call site in every skill untouched. The `ponytail:` comment on that helper had called the case "vanishingly rare"; it was the author's own second machine.
- 2026-07-27 (Gotchas #64, #65): **every prompt hook written on Windows was dead on arrival.** Claude Code runs a hook command through bash on every platform, but `_join` quoted for cmd.exe there, so the registered command reached bash as `C:UsersE112323scoopshimsuv.EXE: command not found` — backslashes eaten as escapes — and failed on every single prompt. `shlex.join` now runs on all platforms (a backslash inside bash single quotes is literal). Found on a fresh Windows install while `afterwit doctor` printed `ok claude prompt hook` throughout, because it substring-matched the settings JSON rather than running anything: doctor now **spawns the stored hook string through bash**, the way the harness spawns it. MCP registration was never affected (it stores `command` + `args`, no shell).
- 2026-07-27 (Gotcha #66): **`afterwit init` could not be re-run after the error it told you to fix.** It bailed when no projects folder matched its candidate list — before reading `config.toml` — so "set `projects_root` and re-run" failed identically forever. An existing config now wins over the scan, and `~/OneDrive*/Desktop/Projects` is a candidate, because managed Windows redirects Desktop and `~/Desktop` simply does not exist there.
- 2026-07-27: **`init` on a second device adopts your existing wiki instead of stranding it.** The wiki repo usually already exists by then — `gh repo create` fails on the taken name, and init shrugged, leaving an empty local wiki with no remote while every card sat on GitHub. It now looks the repo up first and adopts it (remote + fetch + checkout of the remote's default branch), only into a wiki with no commits of its own, and warns loudly if that repo is public. Creation is still the fallback when no such repo exists.
- 2026-07-27: **`afterwit --help` crashed on Windows** with `UnicodeEncodeError` — the help text contains `→` and the console is cp1252. stdout/stderr are reconfigured to UTF-8 in `main()`. This was the first command a new Windows user ran.
- 2026-07-27 (Gotcha #71): **`afterwit inject` no longer routes through argparse.** The hook entrypoint promises to fail open — empty stdout, exit 0 — but argparse enforced its own contract first and exited 2 on any flag it did not recognise, before a line of `inject.py` ran. Exit 2 from a prompt hook blocks the turn on Codex and blocks *and erases* the prompt on Claude Code. Caught live: the new `--harness codex` flag was in the installed command but not in the subparser, and every Codex prompt came back `Blocked`. `inject` now parses its own argv and tolerates unknown flags, so no future flag can reintroduce it.

- 2026-07-27 (ADR-040): **servings are attributed to the harness that was actually served.** `log_serving` hardcoded `harness="claude"`, and `session_text_lookup` resolved every session id against `~/.claude/projects`. With Codex now logging servings, each one would have found no transcript, been mined as `skipped`, and stayed unjudged forever — invisible to the kill-switch and re-scanned on every nightly run. The harness is threaded through both, and Codex servings resolve against `~/.codex/sessions/**/rollout-<ts>-<uuid>.jsonl`.

- 2026-07-27 (ADR-038): **afterwit now answers when a command fails.** A new `PostToolUseFailure` hook on `Bash` looks up recorded fixes for the actual error and injects at most three, under the same Manifesto P3 caps as prompt injection. It fires only on red, gates on a genuine non-zero exit — permission denials, classifier refusals and user aborts (`is_interrupt`) are all silent — and biases `error_fix` cards to the top the way the `lookup_error` pull tool does. Requires `afterwit install claude` and a Claude Code restart; hooks are snapshotted at session start.

- 2026-07-27 (ADR-037, Gotcha #59): **injection had disabled itself on 2026-07-26, on evidence that was 74% afterwit talking to itself.** `auto_review` spawns `claude -p`, which inherits the user's `~/.claude/settings.json` — hooks included — so afterwit's own `UserPromptSubmit` hook injected cards into afterwit's own reviewer. A reviewer emits a verdict about a *different* card and never echoes the injected one, so all 56 of those card-servings scored `ignored`: measured hit rate 19.7%, actual 75% on real prompts, and the kill-switch tripped by a single card hit. The same 56 misses also charged the two cards the reviewer kept matching `-0.2` each, down to `usefulness: -5.6` — one of them the project's own design card, durably demoted in the wiki. LLM children now carry `AFTERWIT_INTERNAL=1` and `afterwit inject` returns nothing when it sees it. The 28 poisoned rows are marked `internal`, the usefulness charges are reversed and written back to the wiki, and injection is re-enabled: same window now reads **20 servings, 75% hit rate, disable False**.
- 2026-07-27 (Gotcha #60): **a `SessionStart` hook invoking the removed pre-rename `hh` binary that no reinstall could ever clear.** `_set_hook` identifies afterwit's hooks by `"afterwit" in command`, and `uv run --project .../harness_helper hh inject --mode session` contains no such string — so the dedupe never saw it as ours, every reinstall appended the real hook beside it, and the stale one failed to spawn on every single session start, silently, for the two weeks since the rename. Install already dropped the legacy *MCP* entry by name for exactly this reason; the hook path was the sibling that was never swept. `_is_afterwit_inject` now also matches `" hh inject"` — leading space, so a project path containing those letters cannot delete a neighbour's hook.
- 2026-07-27 (Gotcha #61): **the kill-switch rounded its own verdict past the point of being checkable.** It reported `hit rate 20% over 76 servings (threshold 20%)` for a real rate of 19.74% — reading as a gate that fired while *level* with its threshold, i.e. as a bug rather than a genuine one-card miss — and "76" could not be reconciled against the 40 rows in `servings`, because the counter is per card served, not per prompt. Now `.1%`, and "card-servings".
- 2026-07-27 (Gotcha #57): **"missing or invalid CSRF token" when saving Settings.** The token is minted once per server process, so restarting `afterwit ui` invalidated the one every open tab fetched at boot — every POST 403'd, and the page never re-fetched, so the tab stayed broken until a manual reload it never suggested. The 403 now says to reload and carries `code: "csrf"`, and the page re-fetches and retries once. The auto-review-disabled 403 deliberately does *not* carry the marker, so that path cannot loop.
- 2026-07-27 (Gotcha #58): **changing the embedding model re-embedded nothing.** The `vectors` cache keyed on a hash of the card body alone, so `MODEL_NAME` was invisible to it: a model swap left old-model vectors in place to be scored against new-model queries, with no error and — for the obvious 384→384 upgrade — no dimension mismatch to catch it. The hash is now salted with the model name, which makes any model change self-invalidating on the next `afterwit index --rebuild`.
- 2026-07-26 (ADR-036, Gotcha #53): **`afterwit run` could never break a stale lock on Windows.** The liveness probe was `os.kill(pid, 0)`, and signal 0 *is* `CTRL_C_EVENT` there — so it called `GenerateConsoleCtrlEvent` instead of checking anything, never reported a dead pid, and raised a real Ctrl+C across the console. A crashed run therefore blocked every subsequent run for the full six-hour lock TTL. Replaced with `runner._pid_is_alive`, which uses `OpenProcess`/`GetExitCodeProcess` on Windows and keeps `os.kill(pid, 0)` everywhere else.
- 2026-07-26 (ADR-036): **`afterwit init` wrote a `config.toml` that afterwit could not read, on Windows.** The path was interpolated straight into a TOML basic string, so `C:\Users\...` made `\U` an escape sequence and `tomllib` rejected the file — the first command a new Windows user runs left them with a broken install. It now goes through `config._toml_value`, which `install.py` was already using for the same reason.
- 2026-07-26 (ADR-036, Gotchas #54-56): **the `windows-latest` CI leg is real now.** It had never been green: twelve tests failed and the session was then aborted by the Ctrl+C above, which hid the list behind a bare `KeyboardInterrupt`. Fixed the causes — `str(Path)` compared to POSIX literals, `monkeypatch.setenv("HOME")` (which does not move `Path.home()` on Windows, and let tests write into the real user profile), `shutil.which` returning the PATHEXT-cased `uv.EXE`, and `redact.scrub_home` rewriting a tmp_path that lives under `C:\Users`. CI jobs also take a 15-minute timeout so a hang is killed rather than left to the 6-hour default.
- 2026-07-23 (ADR-035, Gotcha #51): **Codex sessions were recording no model.** The adapter read `session_meta.model`, which Codex never writes — model and reasoning effort live in `turn_context`, per turn. Result: all 79 codex-sourced cards carried `model: null` while claude cards had one, for months, silently. Also **reasoning effort is now captured from both harnesses** (Claude Code stamps `effort` on the record; Codex on `turn_context`) and rides along in each card source. Already-distilled sessions are not re-read, so existing cards keep their gaps.
- 2026-07-23 (ADR-035, Gotcha #52): **`reviewed_by` named the CLI, not the model.** With `auto_review_model` unset — the default — approvals were stamped `reviewed_by: claude-p` (223 cards). Separation of duties is a claim about models, so the field now resolves to the model that actually ran, at its effort.
- 2026-07-23 (ADR-034, Gotcha #50): **harness paths now honour `CLAUDE_CONFIG_DIR` and `CODEX_HOME`.** `~/.claude` and `~/.codex` were hardcoded in five places, so a relocated harness config meant `afterwit install` wrote files nothing loads, `doctor` reported the harness missing, and ingest mined nothing — all without an error. Every path now routes through the new `harness.py` and stays home-relative on Linux, macOS and Windows.
- 2026-07-23 (ADR-034, Gotcha #49): **an unset `distill_model` inherits the harness's own model** instead of the hardcoded `DEFAULT_CODEX_MODEL`, which had already drifted (`gpt-5.6-terra` vs the user's `gpt-5.6-sol`) and silently spent a model the user had migrated off. The constant is now reached only when Codex has no config at all.
- 2026-07-23 (ADR-034): **`distill_effort` is no longer dropped on the `claude-p` driver.** `claude --effort` exists as of Claude Code 2.x; a configured effort was being silently ignored on that path. It is passed only when set, so older CLIs that lack the flag are unaffected.
- 2026-07-14 (ADR-033): **`auto_review = true` now actually drains the queue.** The nightly distilled into the review queue every night but never ran the reviewer — `auto_review` was read only by the manual `afterwit review` command and the UI button, never by the runner. So the queue only grew (to 257). The nightly now has a review stage, gated on the flag and bounded by the run deadline (a large backlog clears over several nights rather than blowing one run's timeout). Abstains and anything past the deadline stay queued for the human.
- 2026-07-14 (ADR-031): **cards you approved no longer come back for review.** A duplicate of a *verified* card was queued rather than merged — protecting the approved body, since merge overwrites it — so every approval became a permanent generator of queue noise. 116 of 371 queued cards were knowledge the user had already approved. Duplicates now corroborate: evidence accrues, the approved wording stands (merge keeps a verified body), and the check runs deterministically before the auto-reviewer, saving 116 model calls on the next run.
- 2026-07-14 (ADR-032): **every prompt was paying the injection hook twice.** Hook presence was tested by exact command string, so a changed command appended a second hook instead of replacing it: double tokens, double latency on a p95<200ms path, and double `servings` rows corrupting the usage signal ranking learns from. Hooks are now identified by what they are; the user's own hooks are untouched.
- 2026-07-14 (Gotcha #45): the operator block told agents the MCP tools were "already warm" and to use the shell CLI if they seemed absent. In Claude Code they arrive **deferred** — a deferred tool looks absent, so Claude skipped MCP, fell through to the sandboxed CLI, and reported afterwit unavailable. Both blocks now say: load them with ToolSearch, THEN conclude they are missing.
- 2026-07-14 (ADR-030): **"unknown record type" no longer fires on every session.** Two causes: Codex added `world_state` and `inter_agent_communication_metadata` on 2026-07-09 (so every session since warned), and the claude source globbed `projects/**/*.jsonl`, sweeping in the workflow runner's `journal.jsonl` — a ledger, not a transcript. Reviewed-benign types are now dropped explicitly and the ledger is excluded by name; a genuinely new record type still warns, because that alarm is the schema-drift detector. Warnings: 94 sessions → **0 across 1,164 files**, with 71,423 events still extracted. `subagents/**/agent-*.jsonl` remain ingested — they are real transcripts.
- 2026-07-14 (ADR-029): **`recall` works again in a fully read-only sandbox.** `codex --sandbox read-only` mounts /tmp, /var/tmp and cwd read-only, so `tempfile.gettempdir()` *raises* — both the old and the hardened TMPDIR-snapshot readers failed there, and `aw recall` reported `index UNREACHABLE` against a healthy 1,497-card index. Reads now degrade in tiers (direct → WAL-replaying snapshot → `immutable=1`), writers checkpoint the WAL so the last tier is exact, and an un-replayable WAL that reads as empty fails loud instead of answering "no results". Also fixes a leak (Gotcha #39) where each sandboxed reader stranded a full 23MB copy of the private index in `/tmp` — 188MB in one day — because cleanup only ran in a `close()` that `recall`, `stats` and `doctor` never call.
- 2026-07-14 (ADR-027): deterministic `ADR.md` / `DECISIONS.md` ingestion now promotes only explicitly identified decision entries (`ADR-*`, `BD-*`, `DD-*`, `DECISION-*`, `D-*`), preserves the source heading in provenance, and idempotently prunes cards created from nested `Context`, `Consequences`, and gotcha headings by the original importer. The capability no-answer probe was refreshed after docs ingestion made its former Stripe/billing query legitimately answerable.
- 2026-07-14 (Gotcha #38): `afterwit lint` now opens the derived index writable, matching its documented behavior of recomputing and persisting drift flags; the previous read-only connection always failed at its first `UPDATE`.
- 2026-07-14 (ADR-028): memory wikilinks now retain graph identity across deterministic import by translating sibling filename targets to their frontmatter titles; wikilink syntax inside inline/fenced code is treated as an example rather than an edge.
- 2026-07-14 (ADR-026): comprehensive reliability repair. ### Security
- 2026-07-10 (ADR-022): **redaction hardened and moved to the card-write boundary.** A live probe of `redact.py` against sixteen credential formats found **nine leaking**: Anthropic (`sk-ant-`), OpenAI (`sk-proj-`), GitHub (`ghp_`/`github_pat_`), Slack (`xoxb-` + webhook URLs), Google (`AIza`), npm, Stripe, `aws_secret_access_key` (AWS's own docs separate it with a space; the generic rule required `:` or `=`), and a PEM header without its END marker — the common truncated paste. All nine now redact, with a false-positive suite pinning that `git@github.com:owner/repo.git` (every SSH clone URL, and the `repo_url` cross-device key) and `foo@bar.py` survive untouched. More important than the missing patterns was **where** redaction ran: only in the four adapters, at ingest — while the distiller, `mcp save_insight` and `afterwit queue` all write cards without touching an adapter, and it is the **card** that gets `git push`ed. `cards.save()` now calls `redact.sanitize()` (secrets + `/home/alice`→`~`), the one door every writer shares. Existing cards sanitize lazily on next write.
- 2026-07-10 (ADR-022): **`afterwit sync` refuses to push a wiki whose remote is a public repo** (`gh repo view --json isPrivate`), unless `allow_public_wiki_remote = true`. The wiki is distilled from private session transcripts. It blocks on proof of public, never on absence of proof — refusing every unverifiable remote would lock out GitLab, bare SSH, and anyone without `gh`, and they would switch the check off. All five security properties are mutation-tested: each was verified to fail when its guard was removed.

### Added
- 2026-07-10 (ADR-021): **auto-review** — `afterwit review` (and a button in `afterwit ui`). ADR-011 required human approval for `verified: true`; the property it was really buying is **separation of duties** — the agent that wrote a card must not clear it. A human was the only reviewer available, not the only one possible. Opt-in (`auto_review = true`, default off), the reviewer defaults to the driver the distiller is *not* using (codex distills → claude reviews), it **abstains** on any malformed/unknown/timed-out response, and deterministic vetoes run *before* the model is ever called: `preference` cards can never be auto-approved (they encode the user's own intent), and a card carrying a `[REDACTED:…]` marker is rejected outright. Approval routes through the same `ui._approve()` a human presses, now stamping `Card.reviewed_by` (`"human"` | model id) into frontmatter, and every auto-decision appends to the per-device audit log. `afterwit review --dry-run` prints verdicts and changes nothing — it works even with auto-review disabled.
